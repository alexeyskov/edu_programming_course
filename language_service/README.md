# Isolated clangd language service

Private HTTP service for C17/C++20 completions, hover, signature help, definitions,
references, symbols, diagnostics and explicit formatting. It never builds or runs
student executables and has no Moodle, database or LLM credentials. Python 3.12+.

## Protocol

`POST /v1/query`: `{workspace_id, build_profile, files:[{path,content}], method,
path, position?:{line,character}, context?:{...}}`. Workspace ID is a backend-generated
64-character lowercase hex digest scoped to the authenticated principal and document
scope. Never trust a client-provided identity. Positions are zero-based UTF-16 LSP
positions. All eight runner profiles (`cpp-{gcc,clang}-c++20-{single,multi}` and
`c-{gcc,clang}-c17-{single,multi}`) use matching fixed compiler/standard names. Clang
diagnostics remain advisory, not a substitute for the actual runner compiler.

Response: `{result: LSPResult, diagnostics:[{path,diagnostics:LSPDiagnostic[]}]}`.
Location `uri`/`targetUri` values are **relative workspace paths**, not server URIs.
External locations, commands, opaque resolution data and remote edits are removed.
Header completion works, but navigation into system headers is deliberately excluded.
Completion does not auto-insert include directives. Formatting changes are returned,
not applied to files by the service.

Headers: `X-Code-Intelligence-Timestamp`, `X-Code-Intelligence-Nonce`,
`X-Code-Intelligence-Signature` (`v1=` + hex HMAC-SHA256). Sign UTF-8 bytes of
`timestamp\nnonce\nPOST\n/v1/query\nsha256(body)`. Nonces are single-use for five
minutes; timestamp skew is at most 60 seconds. The service has no public port and
must run with exactly **one HTTP worker** (replay protection and pool are in memory).

## Resource and security boundaries

Default four lazy clangd processes, one clangd worker thread each, 180-second idle
expiry. At capacity, the least-recently-used unlocked session is evicted. Active
sessions cannot be evicted. Snapshot synchronization plus each operation is serialized
per session; up to four requests can wait/use one workspace within the total
deadline. Excess callers receive 503 and retain browser fallback completions.
Eight-second **total** request deadline includes cold startup. Cancellation, timeout,
invalid protocol and shutdown kill the process group and delete that session's files.
Maximum 64 source/header files, 2 MiB total UTF-8 source, 3 MiB HTTP request, 1 MiB
response/frame, 200 completions, 100 diagnostics/file. Config files and arbitrary
compiler flags are not accepted. Compiler commands are generated by the service.

`CODE_INTELLIGENCE_ISOLATION=container` is the default. It preserves the existing
runner's Docker filesystem boundary and does **not** require Landlock or Linux 6.2.
The separate non-root container remains read-only, with a bounded workspace tmpfs,
dropped capabilities and CPU/RAM/PID limits. It does not provide per-workspace
filesystem isolation: clangd may read other sessions' files and container process
information through `/proc`. Clearing the child's environment alone does not
hide the parent service's environment/HMAC key from same-UID processes. Never
mount host source directories, application secrets or a Docker socket into this
container; never provide it with database, Moodle or LLM credentials.

For stricter per-workspace protection, explicitly set
`CODE_INTELLIGENCE_ISOLATION=landlock`. This optional mode requires **Landlock
ABI >=3 (usually Linux 6.2+)**. It grants access only to the current workspace and
read-only compiler headers, libraries, the clangd executable, loader cache and
null/random devices. Other workspaces, `/proc`, `/etc` secrets and service code are
inaccessible; workspace execution is denied. Explicit Landlock mode fails closed
if unsupported and never silently downgrades to container mode.

Both modes use the same C launcher, resource limits and seccomp restrictions on
x86-64 or arm64; a failed seccomp/clangd probe prevents readiness in either mode.
No privileged container, user namespaces or added capabilities are needed.
Seccomp denies networking, additional processes (threads are allowed), namespace
APIs, process inspection and cross-process signals. Environment is rebuilt without
secrets; project/user `.clangd` configuration, clang-tidy,
background indexing and compiler query-driver execution are disabled. Memory defaults
to 1024 MiB address space per clangd; the container adds an aggregate memory/CPU/PID
budget. Source files are temporary and are never logged.

Deploy read-only rootfs, non-root UID/GID 65532, `cap_drop: ALL`,
`no-new-privileges`, a private network, a bounded workspace tmpfs (mode0700,
uid65532/gid65532,noexec), and no host source/secret mounts. Toolchain files in the
image are trusted. Do not mount secrets below allowed compiler library directories.
`GET /health/ready` reports `ready`, the selected `isolation` mode, and
`filesystem_isolated` (true only for a ready Landlock service). These modes are not
equivalent security guarantees. The compiler/runner service is not modified.

Settings: `CODE_INTELLIGENCE_SHARED_SECRET` (or `_SHARED_SECRET_FILE`, at least32
bytes), `_WORK_ROOT`, `_MAX_SESSIONS`, `_IDLE_SECONDS`, `_REQUEST_SECONDS`,
`_PROCESS_MEMORY_MB`, `_ISOLATION` (`container` or `landlock`). Clangd/launcher paths can be configured by `_CLANGD` and
`_SANDBOX_LAUNCHER` for trusted deployments. Never expose these settings to students.

## Tests

`python -m pip install -e '.[test]'` then `pytest`. Native integration tests use a
constructor-only unsandboxed test switch; production environment cannot enable it.
Linux tests exercise both production modes, seccomp restrictions in both, and
denial of sibling-file reads in Landlock mode. A compile-only test shim verifies
that a kernel without Landlock accepts container mode but rejects explicit
Landlock mode; no production bypass environment variable is added.
Before enabling for a whole class, measure latency and memory under the
expected concurrent load; keep runner/backend and autosave independent of this service.
